# Longitudinal metric arithmetic — development checkpoint

Implemented `scripts/longitudinal_metrics.py` as pure functions over supplied
prediction ledgers. It has no file loader, CLI, model execution, random sampling,
or default scientific grids/targets. This does not authorize new state collection,
test access, or final protocol freeze.

## Implemented

- `summarize_forgetting`: fixed image IDs/true labels across checkpoints; full
  class universe and explicit old-class subset; only declared retention times
  enter the peak. Returns old-class accuracy/Macro-F1/macro recall curves,
  per-class initial/peak/final recall, per-class forgetting and its mean.
  Predictions of novel classes on old examples remain errors.
- `summarize_uptake`: supplied post-purchase event counts identify observations
  at explicit class-label purchase milestones, plus the final state. Targets
  are caller-supplied. Never-registered, never-reached, undefined relative
  target when final recall is zero, unavailable milestones, and later observed
  drops are explicit. Missing required observations are errors, not interpolated
  results. Predictions of the novel class before its first purchase are rejected
  under the paid-registration policy. First observed crossing is not sustained
  stabilization or exact crossing time.
- `normalized_aulc`: complete explicit budget grid, trapezoidal area normalized
  by grid width. The approved Experiment-A grid gives division by 400. Do not
  use this label-efficiency interpretation for Experiment-B actual-spend curves.
- `paired_seed_summary`: explicit matched seeds, signed left-minus-right values,
  mean, sample SD, median and stream count. One stream has undefined sample SD.
  No confidence interval, significance or equivalence claim is produced.

Callers remain responsible for matching arm, policy, budget, population, and
source provenance before passing ledgers/paired values. Helpers validate IDs,
labels, grids, bounds and missingness, but cannot authenticate externally supplied
event histories. These are arithmetic primitives, not a scientific release tool.

For forgetting reduction use comparator minus HDC with scale=100 (percentage
points); for predictive contrasts use HDC minus comparator. Do not infer those
directions from a favorable outcome. The prototype and gradient controls remain
mandatory; no new method-ranking evidence was generated by this implementation.

## Settings approved for bounded development on 2026-09-11

The user approved the existing draft settings for **development only**:

1. Experiment B: budgets 0/25/50/100/200/400; thresholds .05/.10/.20; all six
   learners/both arms/three seeds. Retain uncertainty plus ground-truth-assisted
   novel-class requests. Each purchased label is charged once; no purchase,
   registration or update after exhaustion; report unused allowance. This
   retains the disclosed oracle assumption, not a deployable novelty detector.
2. Retention snapshots at processed-event counts
   `{0,195,196,390,391,585,586,780,781,976}`. Bootstrap is t=0; history event i
   corresponds to t=i+1. Use only these times for forgetting peaks.
3. Novel-class snapshots immediately after purchased labels
   `{1,2,5,10,20,50,100}` where available, plus final. Development uptake targets:
   80% of final recall and absolute recall 0.80. These are approved development
   targets, not thresholds selected from the A25 validation result.

Approval of these settings permits implementation/synthetic checks, not
automatic real runs, full-grid release, benchmark policy freeze or test access.
A1-A4 still need their own resolutions. Existing A25 and historical attempts
remain preserved; any later instrumented run must use a distinct new directory
and explicitly document its purpose, not overwrite or silently replace them.

Capture and A/B accounting are now implemented in [BUDGET_SNAPSHOTS.md](BUDGET_SNAPSHOTS.md)
(2026-09-12). This arithmetic module still does not load or score snapshots.
