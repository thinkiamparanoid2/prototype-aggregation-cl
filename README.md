# prototype-aggregation-cl

Which prototype rules keep a continual crop-disease classifier from collapsing?
A controlled comparison of hyperdimensional computing (HDC) against NCM,
RanPAC-style, Sign-NCM and Median-NCM heads on DINOv3 ViT features, with every
head given the same 400-label stream budget.

[![Tests](https://github.com/thinkiamparanoid2/prototype-aggregation-cl/actions/workflows/tests.yml/badge.svg)](https://github.com/thinkiamparanoid2/prototype-aggregation-cl/actions/workflows/tests.yml)

> **Status: work in progress (October 2026).** All numbers are on a development
> split (`trusted_splits/val.csv`). The test split has never been opened. That
> split also shares recording sessions with training (see below), so read every
> number as a comparison between heads on one split, not as generalization.

What the table supports:

- **Collapse is specific to adapted ViT-B.** There, mean-aggregating heads (NCM,
  RanPAC-style) drop `3_00_0` to 0.017 F1. On frozen encoders and on adapted
  ViT-L all heads land within a few points of each other, and HDC is not the best.
- **Projection alone does not prevent it.** RanPAC-style projects to 10,000
  dimensions but averages, and collapses like NCM.
- **Bounded aggregation alone only partly prevents it.** Sign-NCM bundles signs
  in 768 dimensions: `3_00_0` recovers to 0.29, macro-F1 stays at NCM's level.
- **HDC at D=10,000 matches Median-NCM with one vector per class.** Median-NCM
  stores every confirmed sample. A bounded streaming median loses a median 0.044
  macro-F1 against the exact one
  ([fidelity check](ssl_hdc_pilot/results/mechanism_ablation/streaming_median_fidelity/summary.json)),
  so on this arm HDC is the strongest head that keeps memory constant.
- **The same pattern replicates on public datasets.** On PlantVillage, adapted
  ViT-B: HDC 0.707 vs NCM 0.652; adapted ViT-L: HDC 0.772 vs NCM 0.781. PlantDoc
  shows no difference. See [COMPARISON.md](ssl_hdc_pilot/results/replication/comparison/COMPARISON.md).

No throughput or speed advantage is claimed: the recorded update timers do not
measure it, and HDC's updates were slower than NCM's.

## Session leakage in the split

Every DACON sample comes with the greenhouse sensor log recorded around it.
Photos taken during one recording share that log, so they show the same plants
under the same conditions. [`scripts/session_audit.py`](scripts/session_audit.py)
keys each sample by its sensor log, counts how many evaluation samples share a
session with training, and scores a no-learning baseline that predicts the
majority training label of the sample's session:

| Split | Samples | Share a session with train | Session-lookup accuracy |
|---|---|---|---|
| `trusted_splits/val.csv` | 1,132 | 94.7% | 90.4% |
| `trusted_splits/test.csv` | 1,132 | 95.2% | 89.5% |

(Exact sensor-log key. Keying by recording window instead gives 95.4% / 95.6%
overlap.) The lookup baseline beats every head above on accuracy (0.67 to 0.85),
so absolute scores here say little about generalization. Comparisons between
heads still hold, since every head sees the same split. A session-grouped split
is the next step.

## Reproduce

Python 3.12. Install CPU or CUDA PyTorch first, then:

```bash
pip install -r requirements-torch.txt   # or a CPU build from download.pytorch.org
pip install -r requirements.txt
python -m pytest ssl_hdc_pilot/tests tests -q
python scripts/make_tables.py           # results table above, from saved cells
python scripts/session_audit.py overlap audit/session_keys.csv ssl_hdc_pilot/trusted_splits
```

The tests and both scripts run without the dataset. Rerunning experiments needs
the DACON images in `Data/` and the DINOv3 embeddings (NPZ, about 1 GB), which are
not in this repository. Entry points are modules under `ssl_hdc_pilot/scripts`,
for example:

```bash
python -m ssl_hdc_pilot.scripts.benchmark_study --experiment A --budget 25 --seed 0 \
  --embeddings ssl_hdc_pilot/results/arm_f_vitb16_trusted_all.npz \
  --trusted-split ssl_hdc_pilot/trusted_splits/train.csv
```

[`RUN_COMMANDS.md`](ssl_hdc_pilot/RUN_COMMANDS.md) records the exact commands
behind each completed run. They were run on Windows and use its paths.


Experiment code, tests and audit notes were developed with AI coding
assistants under the team's direction. Every reported number comes from a saved
run, and the integrity receipts in `results/**/PROVENANCE.md` link each table to
the runs behind it.
